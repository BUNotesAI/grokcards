## Phase 5f — 性能

### 5f-1 Quadtree 视口裁剪

**当前**：`src/components/keysight/hooks/useVisibleEntities.ts` 用 O(N) 遍历做矩形相交检测。N=145 的当前数据完全没问题，但旧插件的设计目标是 1000+ cards/whiteboard，O(N) 在那个量级会成为瓶颈。

**目标**：用空间索引（Quadtree）做 O(log N) 视口裁剪。

**参考实现**：旧插件 `~/codes/vibe-coding/obsidian-plugin-keysight/src/utils/Quadtree.ts` 已经有完整的 Quadtree 实现，直接 port 过来即可。在 GraphView 里的用法见旧 GraphView.tsx 的 `quadtree` useMemo（搜 `Quadtree.fromEntries`）。

**新文件**：
- `src/components/keysight/lib/quadtree.ts` — 纯函数 + 类型，从旧插件 port
- `src/__tests__/components/keysight/lib/quadtree.test.ts` — 至少覆盖：
  - 空 quadtree → query 返回 []
  - 单元素插入 + query
  - 100+ 元素分布在多个象限 → query 视口矩形只返回相交的
  - 边界元素（恰好在视口边缘）正确返回
  - 大 spread 数据（坐标跨度 30000+px）的退化场景

**修改**：`useVisibleEntities.ts`
- 接受 `dimensions` map（已有）+ 用它构建 Quadtree
- 替换内部 filter 为 `quadtree.queryRect(...)`
- **保留 force-include**：当前 `editing` / `expanded` 等状态对应的实体即使在视口外也要渲染（参考旧 plugin `forceVisibleIds`）

### 5f-2 LOD 三级渲染

**zoom 阈值**（对齐旧 plugin）：
- `zoom > 0.4` → **lod0 完整卡片**（当前默认渲染）
- `0.1 < zoom <= 0.4` → **lod1 精简**（只有 title + 边框，无 understanding/content/markdown）
- `zoom <= 0.1` → **lod2 最小色块**（一个带 kind 颜色的小矩形，无文字）

**参考样式**：旧插件 `styles.css` 行 1558+ 的 `.ks-graph-card--lod1` / `.ks-graph-card--lod2` / `.ks-graph-card--alias.ks-graph-card--lod2` / `.ks-graph-note--lod2`。CSS 不能直接抄（旧用全局 class，新项目用 inline style + tailwind），但**视觉效果**（背景色、字号、边框）要对齐。

**实现**：
- `useViewport` 派生 `lodLevel: 0 | 1 | 2`，从 GraphView 传给 EntityNode 再传给 CardNode/NoteNode/AliasNode/TaskNode/QuestionNode
- 每个节点根据 `lodLevel` 渲染不同精度
- 容器尺寸不变（lod1/lod2 仍占同样的世界坐标空间），避免 quadtree/section bounds 重算
- **memo 比较器更新**：lodLevel 变化时整批 re-render，但拖拽时不变（拖拽中 zoom 不变）

**测试**：
- `useViewport` 暴露 `lodLevel` 测试（zoom < 0.1 → 2, [0.1, 0.4] → 1, > 0.4 → 0，边界值）
- CardNode 在 `lodLevel=1` 时不渲染 understanding/content（用 RTL queryByText 断言不存在）
- CardNode 在 `lodLevel=2` 时只渲染一个 div + 颜色背景，不含 title 文本
- NoteNode/AliasNode/TaskNode/QuestionNode 同样

### 5f 完成标准

- Quadtree 替换完成，所有现有 useVisibleEntities 测试仍 pass
- LOD 三级在 ≤ 1000 实体的 mock 数据下性能达标（first paint < 200ms）
- 手动验证：用户在白板中 zoom 到 0.05 不卡顿，看到色块形式的全局 minimap 视图

## 项目约定（必读）

来自 `CLAUDE.md`，**严格遵守**：

### TDD 纪律

新功能 / bug 修复都走 **Red → Green → Refactor**，每次转换**必须**人工确认（用户跑测试看输出）。Red 阶段写测试 + stub，确认失败原因正确；Green 写实现让测试 pass；Refactor 不增减测试，只改结构。

**关卡**：用户期望在每个 Phase 完成时看到 test 输出 + 跑过 `cargo test` + `pnpm test` 的全绿截图。不要把整个 5f+6 都写完才一次跑测试。

### Operation Contract

新增/修改有副作用的 pub fn，**强制**写完整 doc comment：

```rust
/// # 操作名称
///
/// ## 前置条件
/// - ...
///
/// ## 执行效果
/// 1. ...
///
/// ## 不做的事
/// - ...
///
/// ## 幂等性
/// ...
///
/// ## 关联操作
/// - [`other_fn`] — ...
```

### Deep Module + Trait-First

- 新模块按 `src-tauri/src/modules/keysight/` 现有结构（domain/commands/models 分层）
- 跨模块依赖通过 trait 而非具体类型（参考 `EntityGraph` / `CardStore` 等已有 trait）
- 测试用 `:memory:` SQLite 直接 store impl，不 mock

### Anti Test Theater

- 测试**不能**复制业务逻辑做断言。用真实代码路径。
- TS 组件测试 mock `commands` from bindings.ts（这不算 theater，因为业务逻辑在 Rust 不在 TS）
- domain 函数测试用真实 `:memory:` Connection

### 数据写回规则

- SQLite 是 source of truth
- 所有写入通过 Rust domain 函数 → SQLite，不绕过
- TS 侧只调 typed command，不解析 error message 做控制流分支

### TS/Rust 职责边界

- **TS 不生成 id**（全部 Rust 返回）
- **TS 不做业务校验**（Rust 负责）
- **TS 不构造持久化格式**（Rust 接收 typed value）

### 注释语言

doc comment + 行内注释**统一中文**（rust `///` `//`，TS `/** */` `//`）。函数名/变量名/类型名保持英文。

### 测试副作用矩阵

新增任何 domain 写函数，同步在 `CLAUDE.md` 的"副作用矩阵"表里登记一行。Code Review 时核对。
