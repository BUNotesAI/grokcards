## Session: Cmd/Ctrl + wheel 缩放崩溃修复

### 背景

用户反馈 GraphView 中 `Cmd + 鼠标滚轮` 做 zoom 时会把应用搞崩。现状是 `GraphCanvas`
只依赖 React 的 `onWheel`，而 React 自己注册的 wheel 监听是 passive 路径，`preventDefault()`
不能保证拦住浏览器/WebView 的默认 page zoom。

### 改动

- `src/components/keysight/GraphCanvas.tsx`
  - 删除 JSX 上的 `onWheel`
  - 改为在 viewport DOM 节点上注册原生 `wheel` 监听
  - 监听选项显式使用 `{ passive: false }`
  - 原生事件只抽取 `metaKey/ctrlKey/delta/clientX/clientY/preventDefault/currentTarget`
    这些基础字段，再转交给 viewport handler
- `src/components/keysight/useViewport.ts`
  - `onWheel` 不再依赖 React synthetic event
  - 在进入 `setState` 之前先计算 `rect/mouseX/mouseY`
  - 避免高频滚轮事件下把事件对象或 DOM 读取放进 state updater
- 测试
  - `GraphCanvas.test.tsx` 新增断言：必须注册一个 `wheel + passive:false` 的原生监听
  - `useViewport.test.ts` 新增断言：缩放逻辑不依赖事件对象在回调返回后继续存活

### 验证结果

- `pnpm test -- src/__tests__/components/keysight/useViewport.test.ts src/__tests__/components/keysight/GraphCanvas.test.tsx`
- 结果：24 files passed, 151 tests passed
- `pnpm build`
- 结果：通过

### 备注

- 这次修的是最可疑、也最符合症状的根因：浏览器默认 page zoom 与应用内 zoom 双重处理冲突。
  如果用户后续仍能复现，再继续看具体平台（macOS WebKit / Tauri WebView）上的 wheel 事件细节。
