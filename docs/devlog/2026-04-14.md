### 用户关键决策（sub-stage 1 review 时确认的建模）

- **Card LinkTo** → 可指向 6 类 entity
- **Note LinkTo + Note SeeAlso(Obsidian)** → Note 支持 link 到 Q/T 和 obsidian 外部文档(推翻原计划的 "NoteLinkTarget 不含 Q/T" 方案,改为 reader 穷尽 match 防御)
- **Section / Task 不主动发边** → 类型层无 SectionLink/TaskLink 变体
- **Alias 独立 edge 能力仅 AliasLink 一种** → Related/SeeAlso 等显示信息通过 `CardToAlias` 反查 owning card 继承

### 建模简化（sub-stage 1 后期的重要 refactor）

原始方案每个 link 变体有独立的 `*LinkTarget` 子 enum。用户答复后发现四个子 enum 形状
一致,统一用 `EntityId` 作通用 target,**删掉了 5 个重复子 enum**。防火墙机制从 "不可
表达"(NoteLinkTarget 无 Q/T 变体)转为 "必须穷尽 match"(reader 处理全部 6 个 EntityId
variant,禁止 `_` 通配)。两种机制都堵住踩坑样例 1 的 silent failure 根因。

### 踩的坑

- **混淆 `section_members` 表与 `section_link` edge** — Sub-stage 1 初稿把
  `section_link` 当作 `SectionMember` edge 变体建模,实际它是 edges 表里的 section→section
  历史数据,section_members 才是独立的成员关系表。用户要求画 2D 表时发现矛盾,回头
  修正:删除 `SectionMember` 变体,`section_members` 表留给未来独立建模的 task。
  教训:"画布数据结构" 和 "DB 表结构" 不一定 1:1 对应,每次建模前先 grep 真实 SQL。

- **CardToAlias 语义一度被当成"冗余"** — 初稿建议 sub-stage 2 拿掉。用户澄清后明白
  它是 alias 继承 owning card 的 Related/SeeAlso 显示的**反查路径**,不是冗余
  (alias 没有独立的 Related/SeeAlso,靠 CardToAlias 回查 owning card)。
  doc 里已写明这个语义,避免未来误删。

- **`test_connect_with_style_and_label` 留下 style/label 参数的技术债** — Sub-stage 2a
  发现这套参数 TS 从未使用、生产代码从未设值,只有一条单测在测。整体退役,DB 列
  保留(始终 NULL),`connect` 签名不再接受 style/label。
